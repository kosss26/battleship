# Тестовая версия на существующем сервере

Переключатель предназначен для текущей установки HOSTKEY в `/opt/battleship`.
Он оставляет рабочую ветку `hostkey` и её файлы на месте. Тест собирается в
отдельном Git worktree: к сохранённому серверному коммиту присоединяется
`origin/design/naval-home`, включая настройки Telegram-реле и Docker.

## Запуск и переключение

Сохраните `scripts/server-version.sh` как `/root/battleship-version.sh`, затем:

```bash
bash /root/battleship-version.sh test
bash /root/battleship-version.sh original
bash /root/battleship-version.sh status
```

Первый `test` делает снимок оригинала, резервную копию базы, собирает новую
версию и включает её. Следующие `test` используют уже собранную тестовую
версию. `original` возвращает сохранённый backend и копию исходного интерфейса.
Для пересборки теста из последнего коммита ветки используйте `deploy`.

Сайт открывается по прежнему адресу. Перезапуск backend прерывает текущие
матчи, поэтому переключайтесь между играми. База общая: прогресс, баланс и
покупки сохраняются и **не откатываются** при смене версии. Новые предметы
могут не отображаться в оригинальном интерфейсе, но остаются в базе.

## Что сохраняется

- Приватные снимки и SQL-резервные копии: `/root/battleship-version-switch`.
- Оригинальный образ закреплён отдельным Docker-тегом.
- Копия оригинального интерфейса находится в `/opt/battleship-www/saved`,
  отдельно от каталога обычных релизов, который может очищаться старым deploy.
- Тестовые исходники лежат в приватном worktree; основной checkout не меняется.

`original-compose.yml` — закрытая копия исходного Compose-файла. Каталог
имеет права 700, файлы — 600. Не публикуйте его и не отправляйте его содержимое
в чат. Секреты не выводятся командой `status`. Относительные пути и обычная
загрузка `.env` сохраняются; раскрытые значения переменных не переиспользуются
как второй Compose-файл и не подвергаются повторной интерполяции.

Снимок оригинала фиксируется при первом запуске для этой тестовой сессии;
он не обновляется при каждом переключении. Не удаляйте сохранённые образы,
каталоги интерфейса или снимки, пока нужен возврат. Восстановление SQL-копии —
отдельное действие; автоматический откат её не восстанавливает.

## Подготовка и восстановление

До перезапуска живого backend скрипт проверяет соответствие Compose-проекта,
сохраняет конфигурацию и образ, объединяет исходники с серверными патчами,
собирает backend и frontend и проверяет результат сборки. Контейнер базы
и его том не перезапускаются и не удаляются: все `up` ограничены `backend`
с `--no-deps`. После успешного health check интерфейс переключается
атомарной заменой символической ссылки.

При ошибке активации скрипт пытается вернуть предыдущий образ и интерфейс.
Неудачная сборка и конфликт Git не переключают работающую версию. Если
автовосстановление не удалось, лог сообщает об этом; сохранённый оригинал
остаётся доступен для команды `original`.

Скрипт останавливается до переключения при неизвестной конфигурации сборки,
дополнительных build contexts, bind mount исходников или локальных изменениях
перед первым снимком. Параметры `BATTLESHIP_*` позволяют проверить его на
отдельной установке; для описанного сервера менять их не требуется.

## Проверка без сервера

```bash
bash -n scripts/server-version.sh
python3 scripts/test-server-version.py
```

Проверка использует реальные временные Git-репозитории и worktree с имитацией
Docker/HTTP: сохранение серверных патчей, защиту конфигурации, закрепление
оригинального интерфейса, повторное переключение без сборки, отказ при ошибке
сборки и автовосстановление после неудачного health check. Реальное включение
на сервере выполняется только при запуске команды через его SSH-консоль.
